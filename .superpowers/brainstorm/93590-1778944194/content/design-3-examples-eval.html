设计三：Few-Shot 示例 + 版本评估

用精选示例锚定输出质量 · 用评估套件量化 prompt 改进效果

Few-Shot 示例系统

这是解决「生成质量不稳定」最有效的手段。精心挑选 2-3 个高质量示例，让模型「看到」什么是好的输出。

示例结构 (JSON)
// prompts/examples/detail_examples.json
[
{
"id": "ex-001",
"scenario": "表单输入校验",
"tags": ["表单", "校验", "边界值"],
"input": {
"module": "用户注册表单",
"sub_features": ["手机号注册"],
"rules": ["手机号11位"]
},
"output": {
"cases": [
{
"title": "输入正确手机号+验证码注册",
"preconditions": ["未注册手机号"],
"steps": ["1.打开注册页", "2.输入13800001111"],
"expected_result": "注册成功，跳转首页",
"priority": "P2",
"category": "正常流程"
}
// ... more cases
]
}
}
]
注入策略
策略 A: 固定示例
选 2 条最通用、最具代表性的示例，每次调用都注入。覆盖最常见场景（正常流程 + 边界值）。
策略 B: 标签匹配
根据需求特征（如「表单」「权限」「支付」）从示例库匹配最相关的 2 条示例。后续可扩展为 RAG。
当前阶段：策略 A
简单可靠，避免引入额外复杂度。示例库积累到 10+ 条后再切换到策略 B。

评估套件 (Evaluation Harness)

解决「不知道改 prompt 是变好还是变坏」的问题。

# prompts/evaluator.py 使用方式
python -m app.prompts.evaluator
--template phase4_module_detail
--dataset eval/datasets/login_scenarios.json

# 评估数据集格式
[
{
"id": "eval-001",
"requirement": "用户登录功能...",
"module": { "name": "登录", "sub_features": [...] },
"expected_min_cases": 15,
"must_cover": ["正常登录", "密码错误", "空输入"],
"quality_checks": ["priority_distribution", "no_duplicates"]
}
]

# 评估指标
• 覆盖率: must_cover 场景是否都被覆盖
• 优先级分布: P0/P1/P2/P3 比例是否合理
• 去重率: 用例间相似度是否低于阈值
• 可执行性: 步骤是否具体（≥ 2 步）、预期是否可验证
• 稳定性: 同一输入跑 3 次，Jaccard 相似度
