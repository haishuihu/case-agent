基于对 backend/app/prompts/ 和 services/ 的代码审查

识别到的核心问题

1. 无版本化 / 不可观测

Prompt 即代码，嵌入在 Python 字符串中，无法追踪哪个版本的 prompt 产出了哪批结果。没有 A/B 测试基础设施

2. 无评估框架

没有自动化的 prompt 质量评估（regression test、eval harness）。无法衡量一次 prompt 修改是变好还是变坏

3. 混合关注点

所有 Phase（需求评审、冒烟测试、模块详情、多视角评审）共享同一个 SYSTEM_PROMPT，但它们的任务完全不同

4. 缺失 Few-Shot 示例

没有 in-context examples 来引导输出质量。单靠指令约束容易产生不稳定输出

5. 缺少 Token 预算管理

没有 context window 感知。大量拼接可能导致超窗截断。cache key 基于全量拼接字符串

6. 无输出护栏 (Guardrails)

JSON 解析失败靠 Markdown fallback + 重试。无 structured output 验证、schema 校验、自动修复层
