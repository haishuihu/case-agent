设计一：Prompt 模板架构

每个 Phase 独立 System Prompt，YAML 模板化，与代码解耦

核心变化：从「一个 Prompt 打天下」到「按 Phase 精准聚焦」

BEFORE
所有 Phase 共享同一个 SYSTEM_PROMPT
SYSTEM_PROMPT (4角色 + 10维度)
↓
Phase1: 需求评审 ← 用同一个
Phase2: 批量生成 ← 用同一个
Phase3: 冒烟测试 ← 用同一个
Phase4: 模块详情 ← 用同一个
Phase5: 评审补充 ← 用同一个
→ 4角色10维度对冒烟测试太重，对模块详情又太浅
AFTER
每个 Phase 独立 System Prompt
Phase1:
「你是需求分析师」
只关注：模块识别 + 模糊点发现
Phase3 (Smoke):
「你是冒烟测试专家」
只关注：核心路径 + 关键异常
Phase4 (Detail):
「你是测试设计专家」
只关注：穷尽覆盖 + 边界挖掘
Phase5 (Review):
「你是质量审计专家」
只关注：遗漏发现 + 质量把关

YAML 模板结构

# prompts/templates/phase4_module_detail.yaml
name:
phase4_module_detail
version:
"2.1.0"
description:
"模块详细测试用例生成"

system_prompt:
|
你是一个资深测试设计专家，专精于单个功能模块的
穷尽式测试用例设计。
核心能力：
- 等价类划分与边界值分析
- 状态迁移测试设计
- 数据组合与正交分析
设计原则：
- 一个用例只验证一个测试点
- 步骤具体到操作级别
- 预期结果可观测可验证
- 需求不明确的用「待确认」标注

few_shot_examples:
[] ← 引用 examples/ 目录
output_schema:
phase4_output.schema.json

与现有代码的关系：Adapter 模式

现有 build_xxx_prompt() 函数 → 保持不变，作为数据组装层
（继续负责拼接 requirement_text + document_contexts + knowledge_context）
↓
新增 PromptManager.render() → 从 YAML 加载模板，注入 context
（替换硬编码的 system_prompt 和任务指令文本）
↓
llm_client.create_chat_completion(system, user) → 调用方式不变
